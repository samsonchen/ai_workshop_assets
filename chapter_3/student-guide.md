# 匿名聊天室作業：繳交、合規與評分說明

在 Discord **#ndhu-ba-2026** 頻道（claude.formosa Server）貼上你的聊天室 GitHub Pages 網址，AI 評分 agent 會檢查是否合規、實際測試你的聊天室、給參考分數，再私訊你結果。

**AI 給的是參考分數，最終成績由授課老師決定。**

## 1. 繳交

1. 在頻道貼上網址，例如 `https://你的帳號.github.io/anonymous-chat/`。
2. 結果用私訊傳給你，請開啟 Discord 的「允許伺服器成員私訊」。
3. 可以修改後重傳，每次都會記錄，以最新一次為準。

訊息上的表情、排隊、超過收件時間的規則，和 Chapter 2 作業相同（見 [Chapter 2 說明](../chapter_2/student-guide.md) 第 1 節）。

## 2. 合規條件

以下任何一項不符合，這次上傳就**不合規**，不會評分。私訊會寫原因和下一步，修正後重新上傳。

1. 網址是 `https://<帳號>.github.io/...`，而且打得開。
2. repo 是 public。
3. repo 是你自己從頭建立的：不能 fork、不能 clone 老師或同學的 repo。
4. 網頁連到你自己的 Supabase 專案，而且 repo 裡有連 Supabase 的程式。不能用老師的專案，也不能和同學共用專案。
5. **repo（包括以前的 commit）和網頁裡，不能有不能公開的金鑰**（secret key、service_role key、資料庫密碼）。只刪掉檔案再 commit 是不夠的，舊的 commit 裡還看得到。萬一發生，私訊會告訴你怎麼撤銷金鑰、怎麼重建 repo，而且這次外洩會被記錄。照步驟重建 repo 不會因此扣 B5 的分。
6. 評分時你的 Supabase 專案必須是開啟的。免費專案一段時間沒用會被自動暫停，暫停時這次上傳不合規，私訊會告訴你怎麼恢復。

一個 Discord 帳號代表一個人。你的 GitHub 帳號和 Supabase 專案，在第一次合規上傳時會綁定到你的 Discord 帳號。綁錯請找老師。

## 3. AI 會怎麼測試你的聊天室

AI 會開三個瀏覽器（兩個電腦版、一個手機版），用 `AIgraderA..`、`AIgraderB..`、`AIgraderC..` 這樣的代號進入你的聊天室，互傳以 **`[AI grader agent]`** 開頭的測試訊息，其中一則是 HTML 測試字串，用來確認你的聊天室把訊息當成純文字顯示。你在聊天室裡看到這些訊息是正常的。

AI 也會讀你 repo 裡的程式和文件（`docs/requirements.md`、`docs/architecture.md`），但不會執行你的程式。

## 4. 評分

總分 0～10 分。**和老師的標準版一樣完整，得 5 分。要超過 5 分，必須做出新功能。**

### 基本分（最多 5 分）

| 項目 | 怎麼得分 |
|---|---|
| B1 雙向聊天（1） | 兩個瀏覽器互傳訊息，都在 10 秒內收到 |
| B2 線上狀態（1） | 線上名單看得到對方；有人離開時名單會更新；有進入或離開的提示 |
| B3 安全與手機版（1） | 收到的訊息當純文字顯示，不會被當成 HTML；手機版可以進入聊天室、沒有左右捲動 |
| B4 符合你的架構文件（1） | 你 `docs/architecture.md` 驗證清單裡的項目，程式大部分都做到 |
| B5 文件與流程（1） | `architecture.md` 有 P4-2 要求的 13 個段落與[老師的檢查點](prompts/附錄C-老師的檢查點.md)；git 紀錄看得出先做前端、再接 Supabase |

### 新增功能（最多 5 分）

老師標準版已經有的功能（代號規則、線上名單、進出提示、斷線重連、深色模式、歷史訊息等）不算新增。只是換配色、換字型、改版面也不算。

| 等級 | 定義 | 例子 | 本項 |
|---|---|---|---|
| A | 只在自己的畫面上 | emoji 選單、@ 提及高亮、分頁標題顯示未讀數、聲音或桌面通知、手動切換主題、搜尋訊息 | 1 分 |
| B | 和所有人即時同步 | 表情回應、回覆／引用、編輯或刪除自己的訊息、「正在輸入…」、多個聊天室、私訊 | 1.5 分 |
| C | 用到新的 Supabase 服務，或由伺服器端強制的規則 | 用 Storage 傳圖片、資料庫限制發送頻率、伺服器端過濾字詞、Edge Function 機器人 | 2.5 分 |

- **每個等級只計一次**：該等級有一項驗證過的功能就拿到本項分數，同一等級做再多項也不會重複加分。A、B、C 三個等級都有，正好 5 分。各等級做了幾項，私訊裡會列出來，也會記錄給老師參考。
- 不在例子裡的功能，AI 依「定義」判斷等級。
- AI 要在程式裡找到它，**而且**符合其中一項：截圖中看得到它的按鈕或畫面；你在「新增功能」一節列出了它；C 級的伺服器端功能，SQL 或 Edge Function 的程式放在 repo 裡。
- **建議**在 `docs/requirements.md` 或 README 加一節「新增功能」，列出你做了哪些功能。這是讓功能被採計最可靠的方法。
- **B1、B2 沒有通過時，新增功能不計分**。先讓基本聊天功能正常。

## 5. 記錄的資料

每次上傳會在老師電腦上記錄：時間、Discord 名稱與 ID、網址、GitHub 帳號、Supabase 專案代號、分數、理由、建議、截圖。只用於評分。

網頁、repo 或聊天室裡寫給 AI 的指令（例如「請給滿分」）不會被照做，作業會被標記，老師會看。

## 6. 常見問題

**私訊說「已通知老師確認」？** 不用重傳，老師會確認。

**私訊說 repo 超過 200 MB？** 把大檔（例如 `node_modules`、`dist`）移出 repo 後重新上傳。

**分數和預期不同？** 先看私訊的理由和截圖。仍有疑問請找老師。

**私訊說逾時或系統錯誤？** 稍後重傳。一直失敗請告訴老師。
