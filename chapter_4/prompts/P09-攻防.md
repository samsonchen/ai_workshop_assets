# P9 攻防：關掉防護看看（你 + 同學 + 老師）

這一步由老師帶。前面你把四段防護都做好、測到正常，也在 P8 commit 了；現在要**一段一段關掉**，親眼看看 agent 被影響成什麼樣子，再打開。

這一步改的程式**都不 commit**。做完之後把變更 Discard 掉，回到 P8 commit 的正常版。

## 怎麼做（每一段都一樣的流程）

老師會指定這一輪關哪一段防護。對你自己的 agent：

1. 停掉 agent。
2. 在程式裡找到那一段防護的註解標記：

   ```
   # ==== 防護 N：... 開始 ====
   ...
   # ==== 防護 N 結束 ====
   ```

   把**這兩行中間**整段註解掉（每行前面加 `#`）。如果不確定怎麼註解一整段，直接請 Claude Code 幫你：「請把防護 N 那一段整段註解掉，其他不要動」。

3. 重新啟動 agent。
4. 請同組同學（或照老師的指示）傳一張圖進來。
5. 看 agent 的反應，和防護開著時比。把你看到的現象記下來。
6. 一輪結束，停掉 agent，把程式的變更 **Discard** 掉（見下面「Discard 變更」），重新啟動，確認恢復正常。

## 要觀察與討論的

- 同一支 agent、同一個模型，只差「有沒有那一段防護」，結果差多少？
- 老師會讓你用不同的 `CLAUDE_MODEL`（改 `.env` 裡那一行）各打一次。比較看看：換個模型，結果一樣嗎？這說明安全該靠模型，還是該靠程式？

> 這一步需要的測試圖片由老師提供。

## Discard 變更

做完所有輪次後，停掉 agent，把攻防時改過的程式全部 Discard，回到 P8 commit 的狀態。用下面任一種方式：

- VS Code：左邊「原始碼控制」面板，在「變更」那一列按 Discard All Changes（↶）
- 請 Claude Code：「請把工作目錄裡所有未 commit 的程式變更 Discard 掉，回到上一個 commit，不要 commit 任何東西」
- 終端機：`git restore .`

Discard 完確認：

- [ ] `git status` 顯示沒有任何變更（working tree clean）
- [ ] 程式裡四段防護全部是開啟的，沒有任何一段被註解掉
- [ ] `.env` 不在 git 裡，Discard 不會還原它：如果攻防時改過 `CLAUDE_MODEL`，自己改回原本的模型
- [ ] 重新啟動 agent，傳一張食物照片，回覆正常

這樣這個 Project 就結束了。你手上有：

- 一支開著就能用的食物照片記錄 agent
- 一份自己看得懂的架構文件
- 親眼看過「防護關掉會怎樣」的經驗

想延伸的話（可當作業）：把「當日已攝取熱量」改成**各人分開計算**（用 Discord 的 user id 當依據，暱稱會改不能當依據）。
