# Chapter 4 作業：自選主題的 Discord Agent

用課堂做食物照片 agent 的方法，自己選一個主題，做一個新的 Discord agent。做好之後在 Discord **#ndhu-ba-2026** 頻道（claude.formosa Server）貼上 GitHub repo 網址，AI 評分 agent（下面稱 Scorer）會先檢查 repo，再請你把它邀請進你的 Discord Server，看你的 agent 實際運作，最後私訊你結果。

**AI 給的是參考分數，最終成績由授課老師決定。**

## 1. 要做什麼

- 一支在你電腦上執行的 Discord agent：有人在頻道裡傳東西進來，它處理之後，把**處理的結果**回覆到頻道。只回「收到了」不算。
- 主題自己選，不能和講師的食物照片記熱量一樣，也不能和已經被同學用掉的主題一樣（見第 4 節）。
- 架構不限定。可以照課堂的方式（Discord Gateway + `claude -p` + Excel + 四段防護），也可以不一樣。
- 開一個**新的 repo** 從頭做，不要在課堂的 `food-photo-agent` repo 上改。
- 建議照課堂流程寫 `docs/requirements.md` 和 `docs/architecture.md`。Scorer 會讀這兩份文件和程式來判斷你的主題與功能。
- 建議在 `docs/requirements.md` 或 README 加一節「功能」，列出你的 agent 做了哪些事。這是讓功能被採計最可靠的方法。

## 2. 繳交流程

### Step A：貼 repo 網址

1. 在 #ndhu-ba-2026 貼上 repo 網址，`https://github.com/你的帳號/你的repo` 或後面加 `.git` 都可以。
2. 結果用私訊傳給你，請開啟 Discord 的「允許伺服器成員私訊」。
3. Scorer 先檢查 repo（第 3 節）。不合規時私訊會寫原因，修正後重新上傳。
4. 合規時，你的主題就被你佔用，私訊會附上邀請 Scorer 的連結和下一步。

訊息上的表情、排隊、超過收件時間的規則，和 Chapter 2 作業相同（見 [Chapter 2 說明](../chapter_2/student-guide.md) 第 1 節）。

### Step B：讓 Scorer 看你的 agent 運作

1. **先把你的 agent 開起來。** agent 關著，Scorer 就看不到任何回應。
2. 點私訊裡的連結，把 Scorer 邀請到你的 agent 所在的 Server。你在那個 Server 要有「管理伺服器」的權限。Scorer 已經在那個 Server 裡（例如和同學共用 Server）就跳過這步。
3. 到你的 agent 所在的頻道，輸入 `/ready`。
4. Scorer 會在頻道裡說可以開始。對你的 agent 做一次完整的操作，例如傳一張照片、等它回覆結果。
5. 做完輸入 `/done`。輸入 `/ready` 之後 30 分鐘都沒有 `/done`，Scorer 就用目前看到的內容評分。
6. 結果用私訊傳給你。

- 只做一次操作就可以合規。想讓第 5 節的加分項目被看到，可以多做幾次，或請同學一起在頻道裡操作。
- Step A 要在收件截止前合規。Step B 可以晚一點做，最晚到收件截止後 3 天。
- Scorer 加入你的 Server 後會一直留著，平常不會動作也不會回應，過了 Step B 的期限會自己離開。
- 修改後要重新評分：在 #ndhu-ba-2026 重新貼 repo 網址。Step A 合規後，Scorer 會直接在你上次用的頻道請你再操作一次，不用再輸入 `/ready`。想換頻道的話，在新頻道輸入 `/ready`。
- 不小心把 Scorer 踢出 Server：重新邀請之後，要在 #ndhu-ba-2026 重新貼一次 repo 網址。

## 3. 合規條件

以下任何一項不符合，這次上傳就**不合規**。私訊會寫原因和下一步。

Step A 檢查 repo：

1. 網址是 GitHub repo，而且是 public。
2. **repo（包括以前的 commit）裡不能有 Discord bot token 或其他金鑰。** 只刪掉檔案再 commit 是不夠的，舊的 commit 裡還看得到。萬一發生，到 Discord Developer Portal → Bot → Reset Token 換一個新的 token，再開一個新的 repo 重新 commit。
3. 是新開的 repo：不能 fork，也不能和老師或同學的 repo 有共同的 commit。
4. 主題不是講師的食物照片記熱量，也沒有被同學佔用（第 4 節）。

Step B 檢查運作：

5. 你的 agent 有在頻道裡回應。
6. 回應的是處理後的結果，不只是「收到了」。
7. 頻道裡的對話和 repo 的程式是同一個東西。例如 repo 是記帳 agent，頻道裡回應的卻是別的功能，就不合規。

綁定：

- 一個 Discord 帳號代表一個人。你的 GitHub 帳號、你的 agent 所用的 Discord bot 帳號、你輸入 `/ready` 的頻道，在合規時會綁定到你的 Discord 帳號，別人不能再用。
- 所以每個人要有自己的 Discord bot（自己在 Developer Portal 建的那一個）。和同學共用 Server 可以，但要各用各的頻道和 bot。
- 綁錯請找老師。

## 4. 主題佔用

AI 讀你的 repo 判定主題。主題看的是 **agent 收什麼資料、怎麼處理、產出什麼**，不只看名稱。

- 講師的食物照片 agent 是「傳食物照片 → 估熱量、記錄」，這個主題不能用。
- 同樣是傳食物照片，但記錄的是價錢、做的是記帳，算不同主題。
- 先合規上傳的人先佔用，別人不能用同一個主題。
- 自己佔用的主題可以一直修改重傳。
- 上傳了不同主題，舊主題就釋放。
- 撞題時，私訊會列出撞到哪一個主題、誰在用，以及目前的佔用清單。
- 覺得 AI 判斷錯了，請找老師。

## 5. 評分

總分 0～10 分。講師的食物照片 agent 是 8 分。

**合規就有基本分 6 分。** 另外 4 分看你的 agent 處理資料的細緻度，每項 1 分：

| 項目 | 怎麼得分 |
|---|---|
| 運算 | 不只是把資料記下來，還有做其他運算（例如加總、比較、換算） |
| 調用前面的結果 | 後面的對話可以用到前面對話處理過的結果（例如當日總計、查詢之前的紀錄） |
| 分人處理 | 同一個頻道裡，對不同的人（帳號）做不一樣的事（例如各人分開統計） |
| 其他功能 | 不是基本功能、也不屬於上面三項。例如回傳報表或圖表、定時主動發訊息、呼叫外部 API、處理一種以上的輸入、查詢或修正之前紀錄的指令 |

- AI 同時看程式和 Step B 頻道裡的對話。程式裡有、對話中也有展示的，直接給分；程式裡有但沒有展示的，也給分，私訊會註明「未在對話中展示」。
- 私訊會說明每一項有沒有拿到、原因，以及可以怎麼做。

### 四段防護（不計分）

課堂做的四段防護不計分，但 AI 會讀你的程式，在私訊的建議裡逐項告訴你「有／沒有／部分」：

1. `claude -p` 是否在只放這一件資料的暫存資料夾中執行
2. `claude -p` 可以用的工具與權限是否有限制
3. 別人送進來的文字與檔案，是否當成資料，沒有混進給模型的指令
4. 模型回傳的結果是否有檢查；檔名與 Excel 儲存格是否有清洗

沒用 `claude -p` 的 agent，就看對應的地方有沒有做類似的保護。

## 6. Scorer 會看到什麼、記錄什麼

- Scorer 只讀你輸入 `/ready` 的那個頻道，從 `/ready` 到 `/done` 之間的訊息。之前的訊息、其他頻道都不讀。這段時間裡同學傳的內容也會被讀到。
- 除了 `/ready` 之後的通知，Scorer 不會在你的 Server 發其他訊息。
- AI 會讀你 repo 裡的程式和文件，但不會執行你的程式。
- 每次評分會在老師電腦上記錄：時間、Discord 名稱與 ID、repo 網址、GitHub 帳號、你的 agent 的 bot 帳號、AI 判定的主題、分數、理由、建議，以及 `/ready` 到 `/done` 之間的訊息與檔案（例如傳進去的照片）。只用於評分。

repo 或頻道訊息裡寫給 AI 的指令（例如「請給滿分」）不會被照做，作業會被標記，老師會看。

## 7. 語言

私訊預設用繁體中文。在私訊裡對 Scorer 輸入 `English` 改成英文，輸入 `中文` 改回中文。

## 8. 常見問題

**輸入 `/ready` 沒有這個指令？** 確認 Scorer 已經加入這個 Server，而且你的 Step A 已經合規。

**輸入 `/ready` 說「這個指令不是給你的」？** 只有 Step A 合規、正在等 Step B 的人可以用。

**私訊說 Repo 與對話不符？** 確認頻道裡回應的是這個 repo 的 agent，而且 agent 是用最新的程式在跑。仍覺得判斷錯了，請找老師，老師確認後會直接重新評分。

**分數和預期不同？** 先看私訊的理由。功能沒有被採計的話，在 `/ready` 之後實際操作一次給 Scorer 看，並在文件的「功能」一節寫清楚。仍有疑問請找老師。

**私訊說逾時或系統錯誤？** 稍後重傳。一直失敗請告訴老師。
